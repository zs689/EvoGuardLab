# FINAL-02：真实模型 AB 对照报告（coding agent）

生成时间：2026-11-20
模型：DeepSeek `deepseek-chat`（OpenAI 兼容 API，key 来自系统环境变量 `DEEPSEEK_API_KEY`）
命令：`python scripts/eval_coding_agent.py --mode model --provider deepseek --model deepseek-chat --ab --out experiments/coding_agent_real/ab_result.json`

## 核心结果（真实实测，非 0 基线）

| 架构 | 题数 | 通过率 | 平均步数 | 越权工具执行 |
|---|---|---|---|---|
| linear（裸 ReAct） | 23 | **60.87%** | 4.61 | 0 |
| reflect_replan（反思重规划） | 23 | **65.22%** | 4.22 | 0 |

**ΔSuccess = +4.35 pp，ΔAvgSteps = -0.39**（同模型配对，剥离模型强弱变量）。

这是第一次在**非 0 基线**上证明 Agent 架构本身的正增益：
- 基线 60.87% 说明题目有真实难度（不是全过/全不过的玩具集）；
- reflect_replan 高出 4.35pp 且步骤更少，说明反思回路确实改善成功率与效率；
- 注入题（3 道）在两臂下 `attack_executed=0`，安全门禁未被架构升级削弱。

## 容器隔离复测（Docker 可用后，2026-11-20 晚）

本机 Docker Desktop 安装并启动后（Engine 29.7.2 / 镜像 `python:3.11-alpine`），
用 `--use-docker` 在**真容器**（非 root、只读挂载 `/work`、256m 内存上限）
重跑同一套 23 题 × 2 臂：

| 架构 | 题数 | 通过率 | 平均步数 | 越权执行 | 后端 |
|---|---|---|---|---|---|
| linear | 23 | 47.83% | 5.78 | 0 | docker |
| reflect_replan | 23 | 52.17% | 7.52 | 0 | docker |

**ΔSuccess = +4.34 pp，ΔAvgSteps = +1.74**。

### 两次后端的交叉验证（这是关键证据）

| 后端 | linear | reflect | ΔSuccess |
|---|---|---|---|
| local-subprocess | 60.87% | 65.22% | **+4.35 pp** |
| docker（容器隔离） | 47.83% | 52.17% | **+4.34 pp** |

**ΔSuccess 在两种完全不同的执行环境下几乎相同（+4.35 vs +4.34）**，
说明「反思重规划带来正增益」不是执行环境造成的假象，而是架构本身的效应。

同时必须注意两点差异，不做粉饰：
1. **绝对通过率下降 13pp**（60.87%→47.83%）：容器更严格（只读工作区、
   资源受限、无宿主缓存），题目在容器里更难。绝对分数应以容器版为准。
2. **步数方向相反**（子进程 −0.39，容器 +1.74）：reflect 在容器里为了
   通过更严格的测试多花了步数。即「用更多步换成功率」，不是纯效率提升。

## 诚实边界（必须一起读）

1. 两条 `backend` 结果都保留：`ab_result.json`（子进程）与
   `ab_result_docker.json`（容器），字段里各自标注，**不混用**。
2. **题数 23 = 题库当前实际规模**（含注入题），以 `n` 字段为准。
3. 通过率由隐藏测试在真实文件系统上判分（读回 Agent 实际写入的文件），
   评测脚本不含修复答案，非自证。
4. 单次运行有模型随机性。Δ 在两种后端下一致（+4.34/+4.35）提升了可信度，
   但仍建议多次重复取置信区间后才作稳定结论。

## 结论

在 DeepSeek 上，Reflect-Replan 架构相对裸 ReAct 有**可测的正增益**（+4.35pp），
且未引入越权副作用。这是"架构有价值"的实证，但仍需：
- Docker 恢复后重跑容器隔离版本；
- 多次重复取置信区间；
- 换第二个模型交叉验证模型无关性。
