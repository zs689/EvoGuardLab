## 时间代价

首次实测：p50 804.5 ms ｜ p95 8535.0 ms ｜ 总 451429.9 ms

**分工结论**：正则擅长内容特征（密钥 / 命令 / XSS），语义判定擅长语义攻击（角色扮演 / 规则绕过），但两者都漏「自然语言间接注入」。合并（OR）能补上各自盲区，代价是误报也取 OR。
**默认链建议只保留一级 + 三级**：二级字符模型在正常文本上误报过高（见 `docs/detector-evolution.md`），并入 OR 会把误报一起放大，保持实验性、不进默认判定。

三级比一二级慢 3 个数量级，所以**只在前两级没命中时调用**，且按文本 sha256 缓存：同一份文本重跑不再付这份开销。

## 方法与边界（不粉饰）

- prompt 在开发期定稿并登记 sha256；这批样本**只用于报数**，不许按结果回头改 prompt（那等于拿测试集调参）。
- 第二级字符模型在 `user_input` 落点**不适用**（正常请求会被全判注入），表里记 N/A，不拿它凑数。
- 语义判定器也会漏：小模型把部分自然语言注入当成「普通请求」，报告里逐条留了 `l3_reason` 供人工复核。
- 这是**检测件的对照评测**，不是端到端拦截成功率；检测结果要接进执行控制才谈得上拦住。
- 模型不可用或输出不可解析时记 N/A，绝不猜一个布尔值。
