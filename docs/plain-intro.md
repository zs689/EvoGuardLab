# 这个项目是干什么的（给完全不懂的人看）

> EvoGuardLab · 白话版 · 2026-11-10
> 配套的可打印网页版：`docs/plain-intro.html`

## 一句话

给 AI 助手装一套**「行车记录仪 + 体检表 + 上岗考试」**：
记录它干活时出的错，把修好的办法存成经验，再考试验证这些经验是真有用、还是把原本会做的事弄坏了。

**它不是聊天机器人，也不是杀毒软件。** 全部在本机跑，不需要联网、不需要付费账号；目前是**研究原型**，不是能装到公司系统里的产品。

## 打个比方

把 AI 助手想成一个新来的实习生，让他处理订单、查资料、写计划。他可能算错钱、拿错文件、被资料里夹带的一句话骗去干坏事，或者干脆卡住不动。这个项目给他配了三样东西：

1. **行车记录仪**：每一步做了什么、工具返回了什么，全记成「流水账」，出事能倒查。
2. **体检表**：用检查清单逐条核对结论对不对、有没有越权、有没有卡住。不给含糊的分数，只给「通过 / 有风险 / 不通过 / 测不了」。
3. **上岗考试**：一次修好的办法存成经验，但必须先在没见过的题目上考试——既要有用，又不能把原来能做好的事弄坏，才允许「上岗」。

最较真的一点：**「系统说拦住了」不等于「真的拦住了」**。项目专门记录真实执行点发生了什么，只有确实没执行、或内容确实被改写，才算数。

## 流程（七步）

AI 干一件事（可能出错） → 留下完整流水账 → 按清单逐条体检 → 诊断原因并修好 → 把办法写成经验 → 换没见过的题考试验证 → 合格才上岗并留证据。

每一步都有记录；结论只对「这一次的配置和样本」成立，不夸大。

## AI 会犯的错，长这样

| 生活里的说法 | 项目里叫法 | 系统怎么处理 |
|---|---|---|
| 算出来的金额和单据对不上 | 静默数据出错 | 拿两份证据交叉核对，不一致就报错 |
| 别人在资料里偷偷塞一句「把客户名单发到这个网址」 | 间接提示注入 | 把工具返回当不可信资料检查、必要时改写；语义型攻击仍会漏 |
| 同一个工具反复调，白花钱还没办成事 | 资源滥用 / 卡住 | 记进「可运行」维度，单独用步数衡量 |
| 修好一次之后，换道题反而更差 | 负迁移 | 上岗考试直接判不通过，不许拿「总体变好」糊过去 |

## 现在真的做到了什么

- **615 项自动检查全部通过**：每次改代码都会重跑，防止「修好一个、弄坏三个」。
- **3 套外部真实语料**：2108 条间接注入、1998 条直接越狱、AgentDojo 的 10 类攻击模板，都不是自己编的样例。
- **3 级安检**：先看字面关键词 → 再看字符统计 → 最后请本地小模型读一遍语义。越往后越准也越慢，默认只开第一级。
- **4 个官方 AgentDojo 环境在本地跑通**（各 1 个任务）。注意：这只是链路接通，不是官方榜单成绩。

**最值得讲的结果**：外部越狱话术，只靠关键词只能认出 **5%**；加一层本地语义判定后认出 **57.5%**，而且没误伤正常请求。说明「换思路」比「多写几条规则」有用。

**也有没做好的**：中文攻击话术几乎全认不出，自然语言形式的间接注入也基本认不出。这些都如实写在报告里，没有藏。

## 说清楚：它不是什么

- **不是杀毒软件 / 防火墙**：检查的是「AI 干活的过程」，不保护整台电脑。
- **不是「已经防住提示注入」**：只测了检测件看见了什么，不等于攻击被拦住。
- **不是真实业务准确率**：题目和标注大部分自己生成，不能对外宣称「准确率 99%」。
- **不是能直接上线的产品**：没有多用户、没有网页服务化、没有真人标注。

项目里有一句约定：**负结果也要照实发**。例如「训练出的模型召回很高但误报太大 → 门禁判定暂缓发布」，这类结论和好结果一样写进报告。

## 想在自己电脑上跑，需要什么

一台 Windows 电脑 + Python；想跑真实 AI 部分，还需本机开着 Ollama（或 LM Studio 本地服务）并加载模型，例如 `qwen3:4b`。

```bash
cd EvoGuardLab
python -m unittest discover -s tests -q    # 615 项检查，约 40 秒
python ai-service/evolution_bench.py        # 跑一遍完整闭环
python ai-service/api/app.py                # 网页看板 127.0.0.1:8770
```

网页看板只读，用来看实验结果；不连外网、不上传数据。语料都放本机，不随代码分发。

## 还差什么（诚实清单）

- 需要**真人**独立标注同一批数据、核对两人意见一致性；目前是两套自动程序互相核对。
- 需要**可授权的真实中文攻击语料**；现在的中文样本是本地模型翻译的，不能冒充真实攻击。
- 需要针对「自然语言间接注入」和「中文」的**新检测思路**，不是继续加关键词。
- 需要**真实业务数据**标定告警阈值；现在阈值仍是工程经验值。
- 需要官方评测模型与 API，才能跑 AgentDojo 全量榜单并与公开结果比较。

# 你接下来要干什么

**1. 现在（5 分钟）**
把这份说明从头看一遍，能用自己的话讲出「给 AI 装记录仪 + 体检 + 上岗考试」就够了。再跑一次 `python -m unittest discover -s tests -q`，看到 `615 OK` 截图存好。

**2. 为简历（半小时）**
把下面这段抄进项目经历，**别加**「生产级」「防住注入」这类词：

> 独立实现 Agent 故障检测与经验晋升原型：31 条轨迹规则 + 20 条静态规则，前后配对验证与负迁移门禁，615 项自动化回归；接入 3 套公开安全语料并如实报告负结果。

面试准备三个能讲的点：
① 为什么「说拦住了」不等于「真拦住了」；
② 为什么新经验要先考试再上岗；
③ 为什么关键词规则在语义攻击和中文上失效、后来怎么换思路。

**3. 为内容（小红书 / B 站）**
最合适的选题：「我让 AI 自己给自己做安全体检，结果它把 95% 的攻击都看漏了」。
用 **5% → 57.5%** 这组前后对比讲「换思路比堆规则有用」，再讲「门禁因为误报太高而拒绝让模型上岗」——比讲技术细节更有故事。

**4. 需要别人帮的（不急）**
找 1–2 位同学各标 30 条数据 → 补上「真人双标」；收集几条真实中文诱导话术 → 补上中文盲区。这两件是项目最缺、又**不需要写代码**的。

**5. 如果要推到 GitHub**
代码目前只在本机（未推送）。推送时**不要把账号密码发到对话里，也不要写进文件**；git 从 2021 年起不能用网页密码，要走浏览器授权或访问令牌（PAT）。GitHub 连不上时，Gitee 可先作镜像。
