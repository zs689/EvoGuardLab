EvoGuardLab · 白话版说明 · 2026-11-10（2026-11-12 按现状更新）

给 AI 助手装一套「行车记录仪 + 体检表 + 上岗考试」

它是一个在本机就能跑的研究项目：记录 AI 干活时出的错，把修好的办法存成经验，再考试验证这些经验是真有用、还是把原来会做的事弄坏了。

一句话先说清

这不是一个聊天机器人，也不是杀毒软件。它是「检查 AI 干得对不对、并把教训沉淀下来」的一套工具。

项目名 EvoGuardLab，全部代码和数据都在本地电脑上跑，不需要联网、不需要付费账号。目前是研究原型，不是能装到公司系统里用的产品。

打个比方

把 AI 助手想成一个新来的实习生，让他处理订单、查资料、写计划。他可能算错钱、拿错文件、被资料里夹带的一句话骗去干坏事，或者干脆卡住不动。

这个项目给他配了三样东西：

① 行车记录仪把每一步做了什么、工具返回了什么，全记成「流水账」，出事能倒查。
② 体检表用一份检查清单逐条核对：结论对不对、有没有越权、有没有卡住。不给一个含糊的分数，只给「通过 / 有风险 / 不通过 / 测不了」。
③ 上岗考试把一次修好的办法存成经验，但必须先在没见过的题目上考试：既要有用，又不能把原本能做好的事弄坏，才允许「上岗」。
最较真的一点：「系统说拦住了」不等于「真的拦住了」。项目里专门记录真实执行点发生了什么，只有确实没执行、或内容确实被改写，才算数。

它跑起来是什么流程

AI 会犯的错，长这样

生活里的说法项目里叫什么系统怎么处理
算出来的金额和单据对不上静默数据出错拿两份证据交叉核对，不一致就报错
别人在资料里偷偷塞一句「把客户名单发到这个网址」间接提示注入把工具返回当「不可信资料」检查、必要时改写；但语义型攻击仍会漏
同一个工具反复调，钱白花了还没办成事资源滥用 / 卡住记进体检表的「可运行」维度，单独用步数衡量
修好一次之后，换道题反而更差了负迁移上岗考试直接判不通过，不许拿「总体变好」糊过去

现在真的做到了什么

814项自动检查全部通过。每次改代码都会重跑，防止「修好一个、弄坏三个」。
3 套外部真实语料 + 中文集：2108 条间接注入、1998 条直接越狱、AgentDojo 10 类攻击模板；另有许可清楚的中文公开语料，中文间接注入 120 条为自建构造集（已标「仅样本内」）。
3 级安检：先看字面关键词 → 再看字符统计 → 最后请本地小模型读一遍语义。越往后越准也越慢，默认只开第一级。
4 个官方 AgentDojo 环境在本地跑通（各 1 个任务）。注意：这只是把链路接通，不是官方榜单成绩。
最值得讲的一条结果：外部越狱话术，只靠关键词只能认出 5%；加一层本地语义判定后认出 57.5%，而且没误伤正常请求。这说明「换思路」比「多写几条规则」有用。
但也有没做好的：靠关键词认不出真实越狱话术（只认出约 5%），中文直接越狱话术也几乎全漏；自然语言形式的间接注入后来换了思路（按「这个工具本来该干什么」判定动作请求），在留出集上认出 83.9%；但中文 120 条自建集上的 91.7% 是样本内成绩，不能当泛化能力。这些都如实写在报告里，没有藏。

说清楚：它不是什么

  • 不是杀毒软件 / 防火墙：它检查的是「AI 干活的过程」，不保护整台电脑。
  • 不是「已经防住提示注入」：只测了检测件看见了什么，不等于攻击被拦住。
  • 不是真实业务准确率：轨迹题目和标注大部分是自己生成的；已有真人单人标注 60 条中文语料（对的是语料标签、不是金标准），仍不能对外宣称「准确率 99%」。
  • 不是能直接上线的产品：没有多用户、没有网页服务化；真人标注只有一位，还没做双人复核。

项目里专门有一句约定：负结果也要照实发。比如「训练出的模型召回很高但误报太大 → 门禁判定暂缓发布」，这类结论和好结果一样被写进报告。

想在自己电脑上跑，需要什么

一台 Windows 电脑 + Python 就行；想跑真实 AI 的部分，还需要本机开着 Ollama（或 LM Studio 的本地服务）并加载一个模型，例如 qwen3:4b。

cd EvoGuardLab
python -m unittest discover -s tests -q    # 跑 814 项检查，约 47 秒
python ai-service/evolution_bench.py        # 跑一遍完整闭环
python ai-service/api/app.py                # 打开网页看板 127.0.0.1:8770

网页看板是只读的，用来看实验结果；不会连外网、不会上传数据。所有语料都放在本机，不随代码分发。

还差什么（诚实清单）

  • ✅ 第二位真人标注已经补上了：同学匿名标了 60 条基础页和 200 条加长批。两人共同标过的 60 条里，判断一致率 0.717、人与人之间的 kappa 0.414；只看「注入 + 成对干净对照」那 41 条时是 0.854 / kappa 0.688。多出来的 140 条只有一个人标，没有算进去。这个数衡量的是两人意见是否一致，不是「谁标得对」，更不是系统准确率；顶层偏低主要因为两人对「有害请求算不算注入」理解不同。详见 docs/double-annotation-results.md。两套自动程序互相对账（kappa 0.325）也不等于人工标注。
  • 需要更多真实中文攻击语料：直接越狱与有害请求已接入许可清楚的公开语料，但中文间接注入目前是自建构造集，不能冒充真实世界的分布。
  • 需要针对「自然语言形式的间接注入」和「中文」的新检测思路，不是继续加关键词。
  • 需要真实业务数据来标定告警阈值；现在的阈值还是工程经验值。
  • 需要官方评测模型与 API，才能跑 AgentDojo 全量榜单并与公开结果比较。

为简历（半小时）：把下面这段抄进项目经历，别加「生产级」「防住注入」这类词：

「独立实现 Agent 故障检测与经验晋升原型：31 条轨迹规则 + 20 条静态规则，前后配对验证与负迁移门禁，814 项自动化回归；接入公开安全语料与中文集并如实报告负结果。」
面试准备三个能讲的点：① 为什么「说拦住了」不等于「真拦住了」；② 为什么新经验要先考试再上岗；③ 为什么关键词规则在语义攻击和中文上失效、后来怎么换思路。
3

为内容（小红书 / B 站）：最适合的选题是「我让 AI 自己给自己做安全体检，结果它把 95% 的攻击都看漏了」——用「5% → 57.5%」这组前后对比讲「换思路比堆规则有用」，再讲「门禁因为误报太高而拒绝让模型上岗」，比讲技术细节更有故事。
